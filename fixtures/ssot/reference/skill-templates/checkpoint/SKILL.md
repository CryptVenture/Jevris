# Jevris checkpoint — reference template, not an installed plugin

Use the planned `jevris_checkpoint` tool only when the trusted Jevris host has registered it. Preserve exact user constraints, current revision, accepted decisions, unresolved failures, running work and mandatory checks. Every fact needs provenance; mark hypotheses and missing evidence explicitly.

Prefer extractive assembly from trusted fields and evidence handles. Jev can select spans, not write a replacement summary. Do not edit raw harness transcripts. Do not claim a checkpoint undoes external side effects or renews expired approvals.

Return the capsule ID, revision, preserved requirement IDs and unresolved items. Creating a capsule is not an instruction to trigger or block native compaction. A current, certified adapter handles any separately requested native action.
